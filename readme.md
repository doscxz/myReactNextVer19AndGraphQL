# React v19

## Описание хука `useTransition`

### Для чего?

`useTransition` — это хук React, который позволяет помечать обновления состояния как **переходы (transitions)**. Переходы — это обновления с низким приоритетом, которые не блокируют пользовательский интерфейс.

### Синтаксис

```typescript
const [isPending, startTransition] = useTransition();
```

- **`isPending`** — булево значение, указывающее, выполняется ли переход в данный момент
- **`startTransition`** — функция для обертывания обновлений состояния, которые должны быть переходами

### Что он делает?

1. **Помечает обновления как некритичные** — React обрабатывает их с более низким приоритетом
2. **Предотвращает блокировку UI** — позволяет React прерывать переходы для обработки более важных обновлений (например, ввода пользователя)
3. **Предоставляет индикатор загрузки** — через `isPending` можно показывать состояние загрузки

### Когда использовать?

✅ **Используйте `useTransition` для:**

- Загрузки данных из API
- Фильтрации и поиска по большим спискам
- Обновлений, которые не критичны для немедленного отображения
- Операций, которые могут занять время

❌ **Не используйте для:**

- Обновлений, критичных для пользователя (например, ввод в форму)
- Обновлений, которые должны быть синхронными
- Простых операций, которые выполняются мгновенно

## Описание хука `useActionState`

### Для чего?

`useActionState` — это хук React, который позволяет управлять состоянием асинхронных действий в формах. Он специально разработан для работы с Server Actions и упрощает обработку отправки форм с отслеживанием состояния загрузки и результатов.

### Зачем?

- **Упрощает работу с формами** — автоматически управляет состоянием формы и результатами асинхронных операций
- **Отслеживание загрузки** — предоставляет флаг `isPending` для отображения индикаторов загрузки
- **Сохранение предыдущего состояния** — позволяет сохранять и использовать результаты предыдущих вызовов действия
- **Интеграция с Server Actions** — идеально работает с React Server Components и Server Actions в Next.js

### Синтаксис

```typescript
const [state, action, isPending] = useActionState<StateType, FormData>(
  async (previousState, formData) => {
    // Ваша асинхронная логика
    return result;
  },
  initialValue
);
```

- **`state`** — текущее состояние (результат последнего выполнения действия)
- **`action`** — функция для передачи в атрибут `action` формы
- **`isPending`** — булево значение, указывающее, выполняется ли действие в данный момент
- **`previousState`** — предыдущее состояние, переданное в функцию действия
- **`formData`** — объект FormData с данными формы

### Когда использовать?

✅ **Используйте `useActionState` для:**

- Отправки форм с серверными действиями
- Загрузки данных на основе пользовательского ввода
- Операций, требующих отслеживания состояния загрузки
- Интеграции с Next.js Server Actions

❌ **Не используйте для:**

- Простых синхронных операций
- Операций без форм
- Когда не нужен статус загрузки

## Описание хука `useFormStatus`

### Для чего?

`useFormStatus` — это хук React DOM, который позволяет дочерним компонентам получать информацию о статусе родительской формы без необходимости передавать пропсы через несколько уровней компонентов.

### Зачем?

- **Доступ к статусу формы** — дочерние компоненты могут узнать, отправляется ли форма в данный момент
- **Избежание пропс-дриллинга** — не нужно передавать статус через множество уровней компонентов
- **Переиспользуемые компоненты** — позволяет создавать компоненты, которые автоматически реагируют на статус формы
- **Упрощение архитектуры** — особенно полезно для компонентов, находящихся глубоко в дереве компонентов формы

### Синтаксис

```typescript
const { pending, data, action, method } = useFormStatus();
```

- **`pending`** — булево значение, `true` когда форма отправляется
- **`data`** — объект FormData с данными формы (доступен только во время отправки)
- **`action`** — функция действия формы (если передана в атрибут `action` формы)
- **`method`** — метод формы ('get' или 'post')

### Важные замечания

⚠️ **Ограничения:**

- Компонент **должен быть внутри** `<form>` элемента
- Хук работает только с формами, использующими Server Actions или функции в атрибуте `action`
- Если форма использует обычный `onSubmit`, хук может не работать корректно
- Хук должен вызываться в клиентском компоненте (с директивой `'use client'`)

### Когда использовать?

✅ **Используйте `useFormStatus` для:**

- Создания переиспользуемых кнопок отправки с индикацией загрузки
- Компонентов, которые должны реагировать на статус формы
- Избежания передачи пропсов через множество уровней
- Компонентов глубоко вложенных в структуру формы

❌ **Не используйте для:**

- Компонентов вне формы
- Форм с обычным `onSubmit` обработчиком
- Серверных компонентов (только клиентские компоненты)

## Описание хука `useOptimistic`

### Для чего?

`useOptimistic` — это хук React DOM, который позволяет клиентскому компоненту управлять локальным состоянием с оптимистическим обновлением, синхронизируя его с серверным состоянием. Это помогает показывать мгновенный отклик интерфейса до завершения серверных операций.

### Зачем?

- Оптимистическое обновление — пользователь видит изменения сразу, не дожидаясь ответа сервера
- Синхронизация с сервером — локальное состояние обновляется в соответствии с результатом серверной операции
- Удобство работы с асинхронными действиями — упрощает управление состоянием при взаимодействии с сервером
- Повышение отзывчивости интерфейса — улучшает пользовательский опыт за счёт мгновенного отображения результатов

### Синтаксис

```typescript
const [state, update] = useOptimistic<T>(initialState, reducer);
```

- state — текущее локальное состояние
- update — функция для обновления состояния с оптимистическим эффектом
- initialState — начальное значение состояния

      reducer — функция (state: T, action: A) => T, которая описывает, как применить изменение к состоянию

### Важные замечания

**⚠️ Ограничения:**

- Хук должен использоваться в клиентском компоненте (с директивой 'use client')
- Предполагается, что серверное состояние обновляется через Server Actions или другие асинхронные методы
- Обновления состояния происходят оптимистично — возможна временная рассинхронизация с сервером

### Когда использовать?

**✅ Используйте useOptimistic для:**

- Управления состоянием с оптимистическим обновлением (например, лайки, избранное, счётчики)

- Компонентов, которые должны моментально реагировать на действия пользователя

- Сценариев, где важен быстрый отклик без ожидания ответа сервера

- Улучшения пользовательского опыта при взаимодействии с сервером

**❌ Не используйте для:**

- Состояния, которое не требует синхронизации с сервером

- Серверных компонентов (только клиентские компоненты)

- Случаев, где ошибки сервера должны сразу прекращать обновление локального состояния

## Описание хука `use`

### Для чего?

`use` — это новый React хук, представленный в React 19, который упрощает работу с промисами и асинхронными данными непосредственно в компонентах. Он позволяет приостанавливать рендер до разрешения промиса, делая обработку асинхронности более декларативной и удобной.

### Зачем?

- **Упрощение работы с асинхронностью** — позволяет напрямую "ждать" промисы в компонентах без дополнительных эффектов или состояний
- **Интеграция с серверными и клиентскими компонентами** — работает и на сервере, и на клиенте, поддерживая согласованность данных
- **Оптимизация рендера** — рендер компонента приостанавливается до получения данных, что исключает промежуточные состояния загрузки
- **Повышение читабельности кода** — код становится более линейным и проще для понимания

### Синтаксис

```typescript
const data = use(promiseOrThenable);
```

- `promiseOrThenable` — промис или объект, который можно "await", возвращает данные после разрешения
- `data` — результат выполненного промиса, доступный сразу после вызова хука

### Важные замечания

⚠️ **Ограничения:**

- Хук `use` должен использоваться только в компонентах, которые поддерживают асинхронное рендеринг (обычно серверные компоненты)
- Не рекомендуется использовать в классических клиентских компонентах с обычным синхронным рендером
- Если промис отклоняется, React может сгенерировать ошибку, которую нужно правильно обрабатывать через boundary-компоненты (например, `<ErrorBoundary>`)
- Поддерживается Suspense для ожидания асинхронных данных

### Когда использовать?

✅ **Используйте** `use` **для:**

- Получения данных из асинхронных источников непосредственно в серверных компонентах
- Интеграции с async/await без явного управления состоянием загрузки и ошибок
- Упрощения кода при работе с промисами и серверными эффектами
- Сценариев, где нужно "приостановить" рендер до загрузки данных (например, SSR или SSG)

❌ **Не используйте для:**

- Традиционных классических клиентских компонентов без Suspense
- Кода, который должен оставаться полностью синхронным
- Случаев, когда требуется детальное управление состояниями загрузки и ошибок вне React Suspense

## Описание хука useDeferredValue

### Для чего?

useDeferredValue — хук React, представленный начиная с версии 18, который помогает откладывать обновления значений для улучшения отзывчивости интерфейса. Он позволяет браузеру приоритизировать более важные операции (например, ввод пользователя) и «отложить» менее срочные обновления визуального состояния (например, обновления результатов поиска).

### Зачем?

- Оптимизация производительности — предотвращает частые и ресурсоёмкие обновления интерфейса при быстром вводе пользователя
- Сглаживание пользовательского опыта — позволяет показывать более плавный интерфейс, избегая «мигания» или подвисания при больших вычислениях или загрузках
- Управление приоритетами обновлений — помогает отделять срочные обновления от менее срочных, улучшая отзывчивость приложения
- Интеграция с Suspense — в сочетании с React Suspense позволяет показывать заглушки, пока отложенные значения обновляются

### Синтаксис

```typescript
const deferredValue = useDeferredValue(value);
```

- value — текущее значение, которое обновляется часто (например, значение из input)
- deferredValue — версия value, обновление которой может быть «отложено» и идет с более низким приоритетом

### Важные замечания

⚠️ Ограничения:

- Используется только внутри клиентских компонентов (нужно 'use client')
- Отложенное значение обычно используется для рендеринга данных с задержкой, не для критичных обновлений UI
- Не заменяет полноценное управление состояниями загрузки или ошибок, а помогает оптимизировать частоту обновлений
- Совместим с Suspense: можно обернуть части UI, зависящие от deferredValue, чтобы показывать fallback во время обновления

### Когда использовать?

✅ Используйте useDeferredValue для:

- Дебаунса или оптимизации ввода пользователя, чтобы не запускать тяжелые операции на каждый символ
- Интеграции с асинхронным запросом данных при изменении input с минимальной нагрузкой на интерфейс
- Улучшения отзывчивости приложений с большим количеством вычислений или сложным рендером данных
- Комбинирования с Suspense для плавного отображения «отложенных» результатов

❌ Не используйте для:

- Обновлений, которые должны быть мгновенно видны пользователю (например, feedback на нажатие кнопки)
- Управления низкоуровневыми состояниями, которые влияют на логику приложения вне UI
- Случаев, где важна точная синхронная реакция без задержек

### Итог

useDeferredValue — это инструмент для повышения отзывчивости интерфейса, позволяющий отложить обновления не критичных для мгновенного отображения частей UI, улучшая пользовательский опыт при работе с часто меняющимися значениями.

## Поддержка компилятора React

Встроенная поддержка React Compiler теперь стабильна в Next. js 16 после выхода React Compiler 1.0. React Compiler автоматически запоминает компоненты, сокращая количество ненужных повторных рендеров без необходимости вносить изменения в код вручную.

Параметр конфигурации reactCompiler был повышен с experimental до стабильного уровня. Он не включен по умолчанию, так как мы продолжаем собирать данные о производительности сборки для различных типов приложений.

```typescript
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
  reactCompiler: true,
};

export default nextConfig;
```

Установите последнюю версию плагина React Compiler:

```terminal
npm install -D babel-plugin-react-compiler
```

При включении этой опции время компиляции в процессе разработки и во время сборки будет выше, так как React Compiler использует Babel.

## Параллельные маршруты default.js требование

Для всех параллельных маршрутов теперь требуются явные default.js файлы. Без них сборка завершится ошибкой.

Чтобы сохранить предыдущее поведение, создайте default.js файл, который вызывает notFound() или возвращает null.

```typescript
// ../@modal/default.tsx
import { notFound } from 'next/navigation';

export default function Default() {
  notFound();
}
```

Или вернуться null:

```typescript
// .../@modal/default.tsx
```

## Импорт атрибутов и модулей JSON

Атрибуты импорта обеспечивают синтаксическую основу для импорта артефактов, не относящихся к JavaScript. Первыми поддерживаемыми артефактами такого рода являются модули JSON:

```typescript
// Статический импорт
import configData1 from './config-data.json' with { type: 'json' };

// Динамический импорт
const configData2 = await import('./config-data.json', {
  with: { type: 'json' },
});
```

Синтаксис объектного литерала после with используется для указания атрибутов импорта. type является атрибутом импорта.

## Promise.try

Метод try() — это один из статических методов объекта Promise. Метод Promise.try() оборачивает результат выполнения колбэк-функции в промис.

Если при выполнении запроса (асинхронной операции) произойдёт ошибка, она будет корректно обработана c помощью catch(), потому что функция вернёт промис в состоянии «ошибка».

Но что произойдёт, если при выполнении getData() возникнет синхронная ошибка, например, при формировании данных для запроса? Функция не вернёт промис, а ошибка останется необработанной.

Рассмотрим на примере:

```typescript
function getData(requestData) {
  // В функции отсутствует проверка типа аргумента
  const url = requestData.url; // ❌

  return fetch(url);
}
```

Вызов функции без параметра приведёт к ошибке TypeError

```typescript
getData()
  .then((result) => {
    // ...
  })
  .catch((error) => {
    // Ошибка не будет обработана
  });
```

Чтобы единообразно обрабатывать ошибки в блоке catch нужно, чтобы функция getData() всегда возвращала промис, даже если внутри синхронный код. В этом нам поможет Promise.try():

Вызов функции без параметра приведёт к ошибке, но она будет обработана,
так как `Promise.try()` возвращает промис

```typescript
Promise.try(getData)
  .then((result) => {
    // ...
  })
  .catch((error) => {
    // Обработка ошибки
  });
```
